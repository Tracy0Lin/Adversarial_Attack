# 以正式實驗為主的單張介面

## 方法與呈現的分工

實驗程式、資料與設定決定方法。網站只負責上傳圖片、傳入已定義的必要資料、呼叫正式流程、顯示真實回傳結果；不從介面滑桿或動畫推造攻擊、風險、ASR、CIDEr或模型描述。

本包完全移除舊網頁程式作為合併來源。若現有網頁保留版型，需將其後端運算與資料來源接到本包的正式流程。

## 攻擊

正式來源是original/project/work_code下三支原檔；MF-tt選擇work_code版，不選舊pilot備份。單張呼叫工具依照原正式參數啟動三支原檔，不使用另一種攻擊演算法替代。

輸入包含source_image、target_image、target_caption。結果包含MF-ii圖片、MF-tt圖片、對應描述、實際命令及日誌。原本384×384、相對相同前處理Clean的L∞<=8/255基準須保留。

## 第一階段與修復

BlipDefenseService串接固定21句描述、CLIP文字embedding、四維特徵、已匯出的scaler/SVM、0.30/0.80分流。Medium修復輸入圖片的標準化版本；High回傳block且final_caption=null；Low回傳原base描述。

formal_stage1.py、formal_features.py、formal_repair.py的核心函式與正式來源AST一致，保留第一與第二階段各自的插值方式。service.py是新整理的呼叫介面，尚未進行GPU端到端驗證，不能將此新增介面的測試狀態冒充原實驗已完成驗證。

## 原五折的案例重現

tools/defend_cli.py預設要求--image-id，依scenario和原fold_test_ids選擇原五折的對應模型。integration.detector會拒絕以某fold模型重播不是該fold測試集合的ID。

對任意新圖片使用的部署模型屬於後續整合工作。CPU匯出工具的--include-deployment-model選項明確另列，預設不啟用；若使用它，仍需獨立驗證，不能將全資料模型的成績或風險分數當成原OOF報告。

## 輸出欄位

正式單張輸出至少包含caption_model、detector_scenario、detector_purpose、decision_margin、risk_score、risk_level、action、features、base_caption、final_caption，以及有修復時的repaired_image_path。

repaired_image_path是伺服器內部檔案路徑，網頁開發者需自行映射成可存取的圖片URL。BLIP任務是圖片描述，不能把question當作已驗證的任意VQA功能；模型沒有真正執行的欄位不得填入預造回答。

## 正式結果的使用

依各實驗情境原結果檔報告指標；單張顯示相似度或是否達標，ASR則必須有明確樣本集合與分母。自然/壓力情境分開、五折/部署用途分開，避免混用。研究統計保留原樣，沒有因為網頁顯示需求改寫。
