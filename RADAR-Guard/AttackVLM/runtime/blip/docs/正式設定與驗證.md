# 正式設定與驗證

## 版本依據

MF-ii 和 generate_captions 與 pilot5_success 備份逐位元組相同。MF-tt 使用 work_code/mf_tt_query.py，其 SHA-256 是 073bb3aa47095038de27b80cfe20f704082fa9ebef277196e30f07596f90dad4，符合8/11正式啟動紀錄；舊備份缺少初始擾動投影及基線重算，不選舊版。

MF-ii正式參數為100steps、epsilon8、alpha1、batch1。MF-tt為8steps、epsilon8、alpha1、query100、subquery50、sigma8、batch1、384×384。這些不等於原腳本argparse的預設，整合工具明確傳入。

## 偵測

原圖+20種轉換的21個文字embedding先正規化，以其均值的單位向量作中心。距離為arccos(clip(cos,-1,1))/pi；分位數method=linear。d_center=平均距離、d_iqr=q75-q25、d_tail=q90-q50、d_q95=q95。特徵順序固定為上述順序。

StandardScaler＋SVC(kernel=rbf,C=1,gamma=scale,class_weight=balanced,probability=False,random_state=20260729)。risk=1/(1+exp(-clip(margin,-60,60)))。Low<0.30、Medium[0.30,0.80)、High>=0.80。原五折先排序唯一ID、以np.random.default_rng(20260729)打亂、array_split成五組，同ID的Clean與MF-tt同折。

已取得實際LAVIS原始碼，固定解碼參數為use_nucleus_sampling=False、num_beams=3、max_length=30、min_length=10、top_p=.9、repetition_penalty=1、num_captions=1。攻擊描述另使用use_nucleus_sampling=True，兩者不混為同一階段。

第一階段的PIL resize與TF.rotate預設行為保留。第二階段以RGB、384×384、BICUBIC讀入輸入圖片，再以cv2.bilateralFilter(d=7,sigmaColor=50,sigmaSpace=7)處理。沒有將偵測的旋轉圖拿來修復。

## 驗證範圍

保留的28個正式來源、資料與環境證據檔以SHA-256核對，保留原始位元組。整合模組中的6個正式函式與來源AST一致。CPU重建以4,000筆原始feature/OOF資料逐筆比對，分類、fold與風險分流都必須一致，margin/risk誤差必須<=1e-8，否則不匯出。完整結果見validation/。

當前檢查環境沒有torch、torchvision、LAVIS、OpenCV或Flask，因此不宣稱已完成完整影像推論、GPU攻擊、Flask或瀏覽器測試。新單張介面和攻擊CLI包裝僅完成語法/來源/CPU部分驗證，需在適當資源時以真實案例做端到端驗證。用原fold模型重播案例可分離「分類器重建」與「影像推論」的差異。

## 結果檔口徑

自然情境cascade_security為572/1000→22/1000、正常保留990/1000；壓力情境1000/1000→28/1000、正常保留995/1000。

自然情境舊stage1_plus_stage2混淆矩陣為FN36、TP964、Accuracy97.7%，因為22張Low MF-tt全被記作FN，其中只有8張原本攻擊成功；再加上Medium的14張得到36。ASR只計算8+14=22張真正成功攻擊。網頁不得把FN36與ASR2.2%當作相同分子的兩種表示；原研究結果沒有被本包修改。

完整source_manifest和環境清單可供後續重現，包內未包含圖片和大型權重。原主機LAVIS模型設定仍指向其既有BLIP checkpoint來源；目前沒有取得快取權重的檔案雜湊，跨主機時需再確認。
